# Timing input and result freshness correction

Approved scope: correct incomplete/cleared timing, second-row initialization, chronological input validation and stale calculation/export state. No merge, push or deployment is authorized by this work.

Branch: `fix/mobile-localized-layout-20261011`. Production base: `44fb64ca28eb16debb5e2df72fac9bf29060ac5a` (version 0.1.0). This correction follows layout/Spanish commit `b4541dad9e6094f4c20a0a3bc966ba5b50254d74`.

## Behavior

- Timing drafts now belong to the parent level row, rather than index-based component state. A newly added row uses the same default dates for display and derivation. Removed rows cannot leave hidden timing or entry-mode state behind. Drafts survive panel remounts and language changes.
- Every date-segment edit is propagated, including clearing and incomplete years/months/days. Partial segments remain visible instead of being discarded by a feedback loop.
- Any incomplete, invalid or reversed calendar timing clears the derived collection timestamp and sets elapsed hours to the existing unresolved-number representation (`NaN`, preserved by the existing session codec). Zero is never substituted for invalid timing. Impossible calendar dates and nonexistent local clock times are rejected. Valid elapsed time retains the existing two-decimal rounding and infusion-start reference; manual-hour synthetic timestamps are unchanged.
- Calculation is blocked before the API request for entered rows with invalid timing. UI-only drafts are stripped from the unchanged request contract. Existing server validation still checks level-pair coherence and other clinical constraints.
- Input revisions replace millisecond timestamps for result freshness. Clinical edits obscure the old result, disable native PDF/note buttons, guard export callbacks, and discard responses submitted against older inputs. Returning inputs to their old values does not revive a superseded result. Language/presentation-only changes do not change the clinical revision.
- Session restore restores drafts, not cached results. Pre-fix calendar sessions cannot distinguish valid timestamps from the observed stale state, so they retain concentration but require calendar timing re-entry. Manual-hour entries remain intact. New versioned drafts preserve partial and complete timing.
- Bedbound timing-prefill changes, including clearing, also recompute or invalidate derived timing. No pilot-dashboard authentication changes were made.
