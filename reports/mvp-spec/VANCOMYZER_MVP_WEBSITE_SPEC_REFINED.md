# Vancomyzer MVP Website Spec — Refined

## Purpose
Define the minimum viable Phase 1 website scope that is sufficient to establish credibility, trust, and a clear first-visit path without expanding into nonessential growth content.

## Refined MVP objective
A first-time visitor should be able to:
1. understand what Vancomyzer is
2. understand why transparency and interpretability matter
3. review a credible sample path (case, workflow, or documentation example)
4. find answers to common first-order questions
5. know the next step if they want deeper evaluation

## Final Phase 1 page set

### 1. Homepage
Purpose:
- primary entry point
- establish positioning
- present trust-building highlights
- provide one strong demo-first next step

Required:
- hero
- differentiator summary
- trust/transparency highlights
- one case preview
- one export/documentation preview
- FAQ preview
- CTA block

### 2. Trust & Evidence page
Purpose:
- make transparency, interpretability, limitations, and evidence-aware language explicit
- support both homepage trust-building and evaluator review

Required:
- what users should review
- transparency principles
- evidence-aware communication
- one case/example
- one export example
- CTA block

### 3. FAQ page
Purpose:
- reduce first-order confusion
- answer the most important practical questions
- support onboarding and trust

Required:
- core dosing workflow questions
- transparency/trust questions
- workflow/documentation questions
- CTA block

### 4. About page
Purpose:
- explain mission and philosophy
- reinforce clinician-first design
- support credibility without overexpanding scope

Required:
- why Vancomyzer exists
- product philosophy
- intended audience
- exploration CTAs

### 5. Contact / Institutional page
Purpose:
- support serious evaluators
- provide a soft, demo-first institutional path
- allow direct inquiry without aggressive selling

Required:
- who the page is for
- why teams may care
- what evaluators should review
- contact/evaluation CTA block

## Explicitly out of MVP scope
These should not be required before Phase 1 launch:
- full resource hub
- full SEO page library
- comparison pages
- feature page set
- newsletter infrastructure
- lead-magnet system
- webinar/event program
- outreach program
- demo deck expansion
- growth content expansion

## Required global reusable assets
These should be selected once and reused:

- one homepage headline/subheadline pair
- one CTA set
- one primary sample case
- one primary documentation/export example
- one FAQ shortlist
- one trust/claims guardrail set

## Reuse rules
- reuse the same strongest case across homepage, trust/evidence, FAQ, about, and contact/institutional where appropriate
- reuse the same strongest documentation/export example across multiple pages
- keep CTA wording consistent across Phase 1
- do not create unnecessary asset variety during MVP build

## Refined implementation logic
Build order should remain:

1. finalize shared assets
2. homepage
3. trust & evidence
4. FAQ
5. about
6. contact / institutional
7. consistency QA pass

Reason:
- homepage and trust page establish credibility
- FAQ reduces confusion
- about supports mission clarity
- contact/institutional depends on trust assets and examples already existing

## MVP success criteria
The MVP is successful if:

- the homepage clearly explains Vancomyzer
- trust and limitations are visible
- at least one strong case/demo path exists
- at least one documentation/export example is visible
- FAQ answers first-order concerns
- contact/institutional page supports credible evaluation
- all messaging remains evidence-aware and guarded

## MVP guardrails
- do not expand beyond the 5 core pages
- do not add new content categories before core pages are coherent
- do not introduce unsupported validation, superiority, outcome, or ROI claims
- keep language clinician-readable, concrete, and cautious
- favor implementation speed and coherence over breadth
