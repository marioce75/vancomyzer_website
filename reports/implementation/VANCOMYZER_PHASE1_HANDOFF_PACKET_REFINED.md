# Vancomyzer Phase 1 Handoff Packet — Refined

## Purpose
Provide a cleaner, implementation-ready handoff package for building the five Phase 1 Vancomyzer pages.

This refined packet is intended to reduce ambiguity for the builder by pointing only to the core documents needed for implementation.

## Phase 1 implementation target
Build the following five core pages only:

1. Homepage
2. Trust & Evidence
3. FAQ
4. About
5. Contact / Institutional

## Final shared asset bundle
The builder should assume the following bundle is locked:

### Shared CTA family
- Explore the workflow
- Review a sample case
- Review a documentation-ready summary
- Explore the Trust & Evidence page
- Contact us / Request a workflow evaluation

### Case mapping
- CASE-001 → Homepage / About / FAQ
- CASE-003 → Trust & Evidence
- CASE-002 → Contact / Institutional

### Export mapping
- quick summary export → Homepage / About / FAQ
- clinical note export → Trust & Evidence / Contact / Institutional

### FAQ shortlist
1. What is AUC-guided vancomycin dosing?
2. How is Bayesian dosing different from traditional PK dosing?
3. Why might AUC interpretation differ from trough-based reasoning?
4. Why does transparency matter in a vancomycin dosing tool?
5. What should clinicians review before accepting a recommendation?
6. Can documentation-ready summaries improve workflow?

## Builder rules
- build only the 5 core pages
- reuse the locked shared assets
- do not invent new asset variants unless implementation is blocked
- keep all copy clinician-readable and evidence-aware
- follow the refined build order
- apply the claims guardrails everywhere

## Recommended build order
1. confirm shared asset bundle
2. build Homepage
3. build Trust & Evidence
4. build FAQ
5. build About
6. build Contact / Institutional
7. run Phase 1 consistency QA

## What is intentionally excluded
Do not include in this handoff/build scope:
- SEO pages
- comparison pages
- feature pages
- resource hub
- newsletters
- lead magnets
- webinars/events
- outreach assets
- demo deck expansion

## Handoff success criteria
The handoff is successful if a builder can answer:

1. what pages must be built?
2. what assets belong on each page?
3. what CTA family is used?
4. what case/export mapping is locked?
5. what wording guardrails constrain the build?
6. what is the build order?

If any of those are unclear, implementation should not start yet.

## Practical handoff note
This refined packet should be treated as the minimum implementation package for Phase 1.
It is not a marketing plan, growth plan, or Phase 2 roadmap.
