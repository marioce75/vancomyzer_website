# Vancomyzer Contact / Institutional Build Blueprint

## Purpose
Translate the refined Contact / Institutional implementation spec into a direct build blueprint for Phase 1.

## Build objective
Create a Contact / Institutional page that:
- helps serious evaluators understand whether Vancomyzer is relevant
- shows what evaluators should review first
- emphasizes interpretability, transparency, and documentation value
- supports soft demo-first exploration before direct inquiry

## Final page section order

### 1. Page introduction
Purpose:
- explain who the page is for
- frame the page as evaluator-oriented rather than sales-oriented

Assets:
- page headline
- short evaluator-focused summary
- primary CTA
- optional secondary CTA

Preferred CTA emphasis:
- primary CTA: Request a workflow evaluation
- secondary CTA: Review a sample case

Guardrails:
- avoid generic enterprise language
- avoid aggressive sales tone
- avoid unsupported claims

---

### 2. Who this is for
Purpose:
- clarify the intended evaluator audience

Selected audience themes:
- antimicrobial stewardship teams
- ICU and ID pharmacists
- clinicians involved in vancomycin dosing review
- clinical leaders evaluating workflow support tools

Guardrails:
- keep this section simple
- avoid overbroad audience claims
- avoid market-segmentation language

---

### 3. Why teams may care
Purpose:
- explain practical evaluator-facing value

Selected value themes:
- workflow clarity
- interpretability of outputs
- visible assumptions and limitations
- documentation-ready summaries

Guardrails:
- avoid ROI claims
- avoid productivity claims
- avoid outcome claims
- keep language evidence-aware

---

### 4. What evaluators should review first
Purpose:
- give evaluators a demo-first review path before contact

Selected assets:
- CASE-002 — Renal function instability
- clinical note style export example
- Trust & Evidence support link

Placement notes:
- one evaluator-facing case preview
- one richer documentation preview
- one support path to Trust & Evidence

Preferred CTAs:
- Review a sample case
- Review a documentation-ready summary
- Explore the Trust & Evidence page

Guardrails:
- use examples before direct contact
- keep the page practical and concise
- do not include multiple cases or multiple export variants

---

### 5. Contact / evaluation CTA block
Purpose:
- provide a clear endpoint for evaluators ready to engage

Allowed CTA options:
- Request a workflow evaluation
- Contact us
- Review a sample case
- Review a documentation-ready summary

Preferred emphasis:
- primary CTA: Request a workflow evaluation
- secondary CTA: Contact us

Guardrails:
- contact should not overwhelm demo-first exploration
- keep CTA tone credible and non-aggressive

## Cross-linking rules
Contact / Institutional must link to:
- sample case
- documentation-ready summary
- Trust & Evidence
- direct contact/evaluation CTA

Do not link primarily to:
- SEO pages
- comparison pages
- newsletters
- feature pages
- resource hub
- growth assets

## Asset map
- intro and audience/value language -> institutional/contact source copy
- case block -> CASE-002
- documentation block -> clinical note style export example
- trust reinforcement -> Trust & Evidence page
- CTA family -> locked shared CTA family, with evaluator emphasis

## Implementation guardrails
- keep section count fixed
- keep one evaluator-oriented case only
- keep one richer export example only
- keep trust-supporting links visible
- avoid institutional overclaiming
- preserve Phase 1 scope

## Builder note
This blueprint should allow implementation of the Contact / Institutional page without inventing new sections, new evaluator-only asset families, or broader enterprise-sales content during Phase 1.
