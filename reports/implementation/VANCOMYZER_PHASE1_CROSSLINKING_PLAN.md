# Vancomyzer Phase 1 Cross-Linking Plan

## Purpose
Define the exact cross-linking strategy between the five Phase 1 pages so the site supports trust-building, demo-first exploration, and low-friction movement.

## Core rule
Every Phase 1 page should offer at least one trust-building next step and one exploration-oriented next step.

## Primary cross-linking strategy

### 1. Homepage
Primary outbound links:
- Trust & Evidence page
- Sample case
- Documentation-ready summary
- FAQ page

Rationale:
- homepage should immediately branch into trust and example-based exploration
- these are the strongest first next steps for a new visitor

Recommended placement:
- Trust & Evidence link in trust highlights section
- Sample case link in case preview section
- Documentation-ready summary link in export preview section
- FAQ link in FAQ preview section

---

### 2. Trust & Evidence page
Primary outbound links:
- Sample case
- Documentation-ready summary
- FAQ page
- Contact / Institutional page

Rationale:
- users who want trust details should be able to immediately review a real case and example
- serious evaluators should have a path to the Contact / Institutional page

Recommended placement:
- Sample case and export links inside the practical examples sections
- FAQ link in supporting guidance or final CTA block
- Contact / Institutional link in final CTA area

---

### 3. FAQ page
Primary outbound links:
- Trust & Evidence page
- Sample case
- Documentation-ready summary

Rationale:
- FAQ should resolve confusion, then push the user toward concrete examples and trust details
- FAQ should not become a dead end

Recommended placement:
- Trust & Evidence link on transparency/review-related answers
- Sample case link on learning/workflow-related answers
- Documentation-ready summary link on documentation/workflow-related answers

---

### 4. About page
Primary outbound links:
- Sample case
- Trust & Evidence page
- Documentation-ready summary

Rationale:
- About page should not end at philosophy alone
- it should move visitors from mission/philosophy into real examples and trust content

Recommended placement:
- Trust & Evidence link in philosophy or design-principles area
- Sample case and documentation links in exploration CTA block

---

### 5. Contact / Institutional page
Primary outbound links:
- Sample case
- Documentation-ready summary
- Trust & Evidence page
- direct contact / evaluation CTA

Rationale:
- evaluators should be able to review example material before contacting
- the page should support both demo-first and direct inquiry paths

Recommended placement:
- Sample case, export, and trust links in “what evaluators should review first”
- direct CTA in final contact/evaluation block

## Cross-linking principles

### Trust-first principle
Where practical, link users toward:
1. Trust & Evidence
2. sample case
3. documentation-ready summary
before asking for direct contact.

### Demo-first principle
If a page explains, it should also offer a concrete example.

### No dead-end principle
No Phase 1 page should end without at least one meaningful next-step link.

### Limited-choice principle
Each page should emphasize only the strongest next-step links.
Avoid presenting too many equally weighted link choices.

## Shared CTA/link family
Reuse these link/CTA patterns across Phase 1:
- Review a sample case
- See how the workflow is explained
- Review a documentation-ready summary
- Explore the Trust & Evidence page
- Contact us / Request a workflow evaluation

## Explicit exclusions
Do not add Phase 2/3 links as primary cross-links in Phase 1, including:
- comparison pages
- SEO pages
- resource hub
- lead magnets
- webinar/events
- newsletter/digest
- feature pages

## Success criteria
The cross-linking plan is successful if:
- each page has a clear next step
- trust-building paths are visible
- users can move from explanation to example easily
- Contact / Institutional remains reachable without dominating every page
- cross-links stay simple and purposeful

## Implementation notes
- use section-level CTAs rather than large navigation expansions
- keep cross-links context-aware
- reuse the same strongest assets and destinations across pages
- prioritize trust and exploration over breadth
