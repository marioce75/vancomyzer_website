# Vancomyzer Homepage Build Blueprint

## Purpose
Translate the refined homepage implementation spec into a direct build blueprint for Phase 1 implementation.

## Build objective
Create a homepage that:
- explains Vancomyzer clearly
- builds trust quickly
- offers one concrete case path
- offers one documentation/export path
- keeps the user moving through demo-first exploration

## Final homepage section order

### 1. Hero
Purpose:
- explain what Vancomyzer is in plain language
- establish transparency and interpretability positioning
- offer a first next step

Assets:
- one final homepage headline/subheadline pair
- primary CTA: Explore the workflow
- secondary CTA: Review a sample case

Guardrails:
- avoid vague branding language
- avoid unsupported claims
- keep wording clinician-readable

---

### 2. Why Vancomyzer
Purpose:
- summarize differentiators
- explain why workflow clarity and transparency matter

Assets:
- short positioning summary
- 3 to 4 differentiator bullets maximum

Suggested differentiator themes:
- transparent assumptions
- clinician-readable outputs
- documentation-ready summaries
- workflow clarity

Guardrails:
- keep this block concise
- avoid feature sprawl
- avoid enterprise-style language

---

### 3. Trust and transparency highlights
Purpose:
- make trust visible before deeper exploration
- reinforce why the product should be reviewed, not blindly trusted

Assets:
- visible assumptions highlight
- visible method/model highlight
- caution/limitations highlight
- documentation-ready communication highlight

Cross-link:
- Explore the Trust & Evidence page

Guardrails:
- trust should be practical, not abstract
- avoid validation or superiority language

---

### 4. Sample case preview
Purpose:
- show one concrete workflow example

Selected asset:
- CASE-001 — Stable adult with preserved renal function

Placement notes:
- short case summary only
- one CTA: Review a sample case

Guardrails:
- do not include multiple cases
- keep the case explanation concise and general-purpose

---

### 5. Documentation/export preview
Purpose:
- show one practical communication/documentation example

Selected asset:
- quick summary export example

Placement notes:
- short preview only
- one CTA: Review a documentation-ready summary

Guardrails:
- do not use the longer clinical-note example here
- keep the preview easy to scan

---

### 6. FAQ preview
Purpose:
- reduce first-order confusion

Selected FAQ preview themes:
- What is AUC-guided vancomycin dosing?
- How is Bayesian dosing different from traditional PK dosing?
- Why does transparency matter in a vancomycin dosing tool?
- What should clinicians review before accepting a recommendation?

Placement notes:
- 3 to 5 short items only
- one CTA: Explore the FAQ

Guardrails:
- keep answers short
- avoid long explanatory blocks

---

### 7. Final CTA
Purpose:
- give the visitor a clear next step

Allowed CTA options:
- Explore the workflow
- Review a sample case
- Review a documentation-ready summary

Guardrails:
- keep CTA tone demo-first
- do not push direct contact as the dominant homepage ending

## Cross-linking rules
Homepage must link to:
- Trust & Evidence
- sample case
- documentation-ready summary
- FAQ

Do not link primarily to:
- SEO pages
- comparison pages
- feature pages
- newsletters
- institutional-heavy flows

## Asset map
- headline/subheadline -> homepage copy source
- differentiators -> homepage copy + trust language
- trust block -> trust/evidence sources
- case block -> CASE-001
- export block -> quick summary export
- FAQ block -> final FAQ shortlist subset
- CTA family -> locked shared CTA family

## Implementation guardrails
- keep section count fixed
- keep one case only
- keep one export preview only
- keep CTA family consistent
- keep copy aligned with claims guardrails
- do not expand homepage scope during implementation

## Builder note
This blueprint should be sufficient to implement the homepage without inventing new page sections or new homepage-specific assets.
