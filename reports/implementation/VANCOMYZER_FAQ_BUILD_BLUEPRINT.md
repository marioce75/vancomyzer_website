# Vancomyzer FAQ Build Blueprint

## Purpose
Translate the refined FAQ implementation spec into a direct build blueprint for Phase 1.

## Build objective
Create a FAQ page that:
- answers the most common first-order questions
- reinforces transparency and clinician oversight
- links visitors to examples and deeper explanation
- keeps answers concise and readable

## Final FAQ section order

### 1. Page introduction

Purpose:
- explain what the FAQ covers
- set expectations that the tool supports interpretation rather than replacing clinician judgment

Assets:
- page headline
- short explanatory paragraph

Guardrails:
- avoid marketing tone
- avoid feature lists

---

### 2. Core FAQ block

Use the final shortlist:

1. What is AUC-guided vancomycin dosing?
2. How is Bayesian dosing different from traditional PK dosing?
3. Why might AUC interpretation differ from trough-based reasoning?
4. Why does transparency matter in a vancomycin dosing tool?
5. What should clinicians review before accepting a recommendation?
6. Can documentation-ready summaries improve workflow?

Implementation notes:

- present questions in logical order
- answers should remain concise
- avoid long clinical essays

Guardrails:

- maintain clinician-readable language
- avoid unsupported claims

---

### 3. Example references

Purpose:
- reinforce FAQ answers with practical examples

Assets:

- CASE-001 reference
- quick summary export example

CTA options:

- Review a sample case
- Review a documentation-ready summary

Guardrails:

- keep examples short
- avoid multiple cases

---

### 4. Trust reinforcement

Purpose:
- connect FAQ answers with the trust model

Assets:

- transparency principles
- clinician oversight themes

Cross-link:

- Trust & Evidence page

Guardrails:

- maintain evidence-aware tone
- avoid claims of superiority

---

### 5. Final CTA

Purpose:
- offer next step after questions are answered

Allowed CTA options:

- Review a sample case
- Review a documentation-ready summary
- Explore the Trust & Evidence page
- Contact us / Request a workflow evaluation

Preferred emphasis:

- sample case first
- documentation example second

---

## Cross-linking rules

FAQ must link to:

- sample case
- documentation-ready summary
- Trust & Evidence
- Contact / Institutional

Do not prioritize:

- SEO pages
- marketing landing pages
- feature lists

---

## Asset map

- questions -> FAQ shortlist
- case reference -> CASE-001
- export preview -> quick summary export
- CTA family -> locked shared CTA family

---

## Implementation guardrails

- keep FAQ count fixed
- keep answers concise
- maintain clinician-readable tone
- avoid marketing language
- preserve Phase 1 scope

---

## Builder note

This blueprint should allow implementation of the FAQ page without adding new FAQ items or new page sections during Phase 1.
