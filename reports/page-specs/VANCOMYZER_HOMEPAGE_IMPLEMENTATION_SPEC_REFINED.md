# Vancomyzer Homepage Implementation Spec — Refined

## Purpose
Define the homepage as a directly buildable, tightly scoped Phase 1 page that explains Vancomyzer clearly, builds trust quickly, and gives first-time visitors a strong next step.

## Refined homepage objective
A first-time visitor should be able to:
1. understand what Vancomyzer is
2. understand why transparency and interpretability matter
3. see one concrete case/example path
4. see one documentation/export example path
5. know what to do next

## Final homepage structure

### Section 1 — Hero
#### Required elements
- one final headline
- one final subheadline
- one primary CTA
- optional secondary CTA

#### Content requirements
- explain Vancomyzer in plain clinician-readable language
- emphasize transparency, interpretability, and workflow usability
- avoid abstract branding language
- avoid unsupported claims

#### Above-the-fold priority
This section must appear above the fold.

---

### Section 2 — Why Vancomyzer
#### Required elements
- short positioning summary
- 3 to 4 differentiators maximum

#### Content requirements
- focus on transparency, clinician-readable outputs, and workflow clarity
- keep differentiators concrete
- avoid feature sprawl
- avoid enterprise-style generic wording

#### Priority
High priority. Should appear early on the page.

---

### Section 3 — Trust and transparency highlights
#### Required elements
- visible assumptions highlight
- visible method/model highlight
- caution/limitations highlight
- documentation-ready communication highlight

#### Content requirements
- build trust before stronger conversion asks
- make transparency practical, not abstract
- connect trust to real review behavior

#### Priority
High priority. This is one of the homepage’s core differentiation blocks.

---

### Section 4 — Sample case preview
#### Required elements
- one primary case preview
- short educational summary
- CTA to review the case

#### Content requirements
- use one strongest general-purpose case
- make workflow interpretation concrete
- support demo-first exploration
- avoid overloading with multiple cases on the homepage

#### Priority
High priority. One case is enough for Phase 1 homepage.

---

### Section 5 — Documentation/export preview
#### Required elements
- one quick summary or clinical-note preview
- one short explanation of why it matters
- CTA to review a documentation-ready example

#### Content requirements
- demonstrate practical workflow value
- reinforce communication/documentation support
- keep the preview concise

#### Priority
Medium-high priority.

---

### Section 6 — FAQ preview
#### Required elements
- 3 to 5 short FAQ items
- CTA to the full FAQ page

#### Content requirements
- address first-order user confusion
- prioritize AUC/Bayesian/transparency/workflow questions
- keep answers short and exploratory

#### Priority
Medium priority. Useful but should not dominate the page.

---

### Section 7 — Final CTA
#### Required elements
- one primary CTA
- optional secondary CTA

#### Content requirements
- direct the visitor to a meaningful next step
- keep conversion demo-first
- maintain trust-oriented tone

#### Priority
Required final section.

## Recommended homepage CTA family
Use one consistent CTA family throughout:
- Explore the workflow
- Review a sample case
- See how calculations are explained
- Review a documentation-ready summary

## Refined asset requirements
The homepage should only require:
- one final headline/subheadline pair
- one positioning summary
- one trust-highlights block
- one sample case preview
- one export preview
- one FAQ shortlist
- one CTA set

## Explicit exclusions
Do not add these to the Phase 1 homepage:
- multiple case grids
- pricing complexity
- large resource-hub navigation blocks
- feature-page depth sections
- institutional-heavy messaging
- newsletter/email capture emphasis
- social proof claims that are not yet substantiated

## Homepage success criteria
The homepage is successful if:
- the product is understandable in one pass
- trust and caution are visible
- one strong case path is clear
- one strong export/documentation path is clear
- the CTA path is obvious
- the page remains simple and credible

## Implementation guardrails
- keep homepage section count fixed to the refined structure
- prefer tighter copy over longer explanation
- do not replace trust with promotional language
- do not introduce unsupported claims
- reuse the same strongest selected assets instead of expanding choices
